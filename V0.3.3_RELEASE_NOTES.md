# VEDA v0.3.3 Release Notes

## Headline

VEDA v0.3.3 delivers a full UI hardening pass, a rewritten execution visualizer, and a major resolver-path performance win without changing decision outcomes.

## UI — every rounded edge removed, system rebuilt

The prior visual system had been overgrown with a block labelled "2026 visual system" that appended 54 `border-radius` declarations to the main stylesheet. That block is now gone. The web app is rebuilt around a hard-edge design language:

- 1px hairline borders and square status marks
- globe-safe CSS tokens with no rounded corners
- cards and metrics aligned to a shared baseline in multi-stat rows
- header and panel layouts that wrap instead of colliding
- chart points rendered as squares instead of circles to match the square-only visual language
- no SVG circle-based decorative graphics in the active web assets

This was not just cosmetic. We also repaired several UI logic and styling bugs that surfaced during the rebuild:

- "Decisions waiting on you" showed `152` instead of `17` because `views.js:313` was concatenating formatted strings instead of numeric values.
- `.lab`, `.voice`, and `.photo` were used in markup but never styled.
- The drop zone referenced `var(--paper-2)`, which did not exist.
- `VIEWS.noproject` opened a `<div>` and closed a `</section>`.
- Chart colours were hard-coded hex values and were not visible in the light theme.
- Dead `.bar.dual` styling was removed.
- Duplicate entries in `.gitignore` for `VEDA_GOOSE_BENCHMARK/` were cleaned up.

## Execution visualizer — rewritten

The old execution map was drawing by percentage guesswork and overlap. It used awkward positioning, negative z-index connectors, and a packet animation that crossed label text. It also skipped stages 1–3 entirely, creating a visual gap in the process rail.

The new execution visualizer is a single top-to-bottom pipeline where all stages are present as real nodes in the rail. Bands are implemented as CSS grids; rails are explicit elements between bands; and nothing is layered on top of the text or other stages. The full 8-stage pipeline now renders correctly in both dark and light themes.

We verified this with headless rendering in Edge and by extending the repo's `execution_ui_regression_test.js` to assert each band's declared column count matches the actual nodes inside it.

## Performance

Resolver path performance improved materially without changing decisions.

- **43.4s → 10.7s** on the 120-evidence / 900-activity benchmark
- **4.1× faster** with **bit-identical decisions**
- Equivalent results were confirmed using a two-pass harness that forced every memoisation off in one pass and compared persisted outputs in the other pass

We also verified identical persisted link outputs across all 480 expected links: activity, relation, rank score to 9 decimal places, and calibrated confidence.

The main bottlenecks fixed were:

- `sequence.score_candidate` was rescanning all activities across all projects for each candidate
- `tree_resolver._index` and `rescheduler._index` paid a freshness `COUNT(*)` cost on every candidate despite cached state
- `_date_corroboration` re-read and re-tagged the whole evidence table for each row, creating O(n²) work
- `_graph_features` ran 2 queries per candidate
- `_signal_features` reparsed the same metadata JSON for each document row
- SQLite was configured with `synchronous=FULL` and a commit per row write, which incurred an fsync per link

Beam-search memoisation remains exact: `_pred_readiness` only reuses a cached answer when none of that activity's predecessors are in the hypothesis set.

### Agent wake and frontend responsiveness

- `antigravity_local` was polling every 2 seconds; it is now signal-driven using `/api/agent/inbox` and `/api/agent/result`
- There is adaptive backoff from 50ms to 1s as a fallback
- The frontend no longer blanks the view to a spinner on every SSE event, preserving scroll position
- Duplicate GETs are coalesced for 400ms and cancelled on any write
- The run animation repaints locally at 320ms instead of refetching full data
- The durable poll interval moved from 720ms to 1500ms

### Control-room and indexing improvements

- Control-room overview queries dropped from roughly **25 queries to 3**
- **13 hot-path indexes** were added for faster lookups and more stable performance

## Summary

v0.3.3 is the release where the product became visually consistent, the execution pipeline became truthful and readable, and the resolver path became materially faster without changing the decisions. It is the current baseline for the hard-edge UI and the structurally corrected execution rail.
