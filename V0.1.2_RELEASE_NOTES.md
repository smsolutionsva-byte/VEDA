# VEDA v0.1.2

## Multi-source ingestion

- Stage many files across repeated Browse selections.
- Drag/drop files and paste clipboard screenshots.
- Combine files and pasted field text in one ingestion batch.
- Pasted modes: field note, WhatsApp/chat transcript, schedule change request.
- Exact SHA-256 duplicates are idempotently skipped.
- Every source keeps batch/source-mode provenance.

## Documents and OCR

- Added PNG/JPEG/BMP/TIFF/WebP evidence.
- PDF embedded text is extracted first.
- Only text-poor/scanned pages use local RapidOCR + ONNX Runtime.
- OCR results are cached next to the immutable source copy.

## Incremental schedule handling

- Evidence-only batches reuse the current schedule snapshot.
- A genuinely new schedule creates a new revision.
- Revisions record added, removed, and updated activities by stable Horizun UID.
- Revision-delta API and Files-page summary added.

## Change requests

- Explicit human change-request text is HUMAN_INPUT rather than an untrusted
  document instruction.
- Agent schema now represents task update/create/delete explicitly.
- All operations remain proposal-only until validation + Horizun dry-run + human
  approval.
- Deleting a task that has children is refused to prevent accidental cascade.

## Reliability

- Includes the v0.1.1 queue/SSE recovery fixes.
- Version reporting is unified on `veda.__version__`.
- Existing virtual environments install the new OCR dependencies automatically.

## Reference basis

- MDN File API / `multiple` / `FileList` / `DataTransfer.files` for multi-file, drag/drop and clipboard file intake.
- PyMuPDF OCR guidance for OCR-on-demand rather than OCR-ing every PDF page.
- RapidOCR current docs for `RapidOCR()` + ONNX Runtime and `RapidOCROutput.txts`.


## Provider fallback hotfix

Reasoning now defaults to `auto` and attempts providers in this exact order:

1. **Antigravity** through the official `agy` headless CLI (uses the operator's existing Antigravity authentication; no Gemini API key required).
2. **Claude Code** when Antigravity is unavailable or the run fails.
3. **Codex** when Claude Code is unavailable or the run fails.
4. VEDA's deterministic analyser only if all three are unavailable.

Provider failures no longer pin the single global worker. Antigravity and Codex are run in isolated temporary workspaces and receive only VEDA/Horizun read-only MCP access; schedule mutation still requires VEDA's proposal/dry-run/human-approval pipeline.
