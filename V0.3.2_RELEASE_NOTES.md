# VEDA v0.3.2 Release Notes

## Headline

VEDA v0.3.2 makes **contextual four-expert MetaRank** the default schedule-entity-resolution path.

## New resolver architecture

- Semantic retrieval is a permanent shared candidate floor rather than a last-resort fallback.
- EngineeringRank contributes physical/engineering identity evidence.
- TreeRank contributes hierarchical parent/child/sibling/ancestor and granularity evidence.
- Rescheduler v2 contributes reality-first changed-world and opportunistic/OOS planning evidence.
- Candidate lists are deduplicated by stable activity UID and fused by learned expert-utility models plus XGBoost LambdaMART MetaRank.
- No benchmark category labels or hardcoded routing rules are used by the learned router.

## Safety and score semantics

- Raw LambdaMART margins are retained in `meta_rank_raw` and are **not treated as probability**.
- A fixed monotonic bounded ranking transform is used only for downstream rank-score compatibility.
- Engineering safety features survive fusion.
- Calibration, deterministic validators, human review and schedule-write policy remain independent downstream gates.
- Model/schema incompatibility fails to utility-weighted RRF rather than silently mis-scoring.
- Individual expert failures are isolated and recorded in diagnostics.
- Explicit legacy flags preserve pre-v0.3.2 ranking behavior for reproducibility.

## Frozen unseen holdout

170 exact-identity cases; 13,412 activities; 10,120 relationships.

| Resolver | Top-1 | R@3 | R@5 | R@10 | MRR |
|---|---:|---:|---:|---:|---:|
| Semantic | 39.41% | 52.35% | 59.41% | 77.65% | 0.4970 |
| Engineering | 53.53% | 72.94% | 78.24% | 84.12% | 0.6397 |
| Tree | 59.41% | 77.06% | 78.82% | 83.53% | 0.6899 |
| Rescheduler v2 | 47.65% | 63.53% | 72.94% | 78.24% | 0.5968 |
| Hard expert router | 77.65% | 83.53% | 84.71% | 90.00% | 0.8109 |
| Utility-weighted RRF | 73.53% | 84.71% | 85.88% | 90.59% | 0.7939 |
| **MetaRank** | **85.88%** | **94.12%** | **96.47%** | **97.06%** | **0.9018** |

Correct-activity recall in the four-expert candidate union was **100%** on this holdout.

## Important limitations

- The reported frozen holdout used the deterministic hash retrieval backend for architecture isolation; re-run the same frozen holdout locally with BGE-M3 + bge-reranker-v2-m3 for production semantic-quality estimates.
- Rescheduler v2 is compute-intensive on some adversarial cases; v0.3.2 prioritizes accuracy and correctness over sparse expert activation.
- Early-material / newly changed resource-constraint reasoning and very weak implicit OOS identity remain known weak regimes.
- MetaRank accuracy does not authorize automatic schedule writes; calibration and risk policy remain mandatory.

## Dependencies

Install routing dependencies with:

```bash
pip install -r requirements-routing.txt
```

This installs XGBoost, scikit-learn and NumPy versions used by the learned routing/fusion layer.
